# brew.

VPN-клиент на базе ядра [mihomo](https://github.com/MetaCubeX/mihomo) с дизайном Material You.
Flutter: Windows и Android; далее macOS и Linux.

## Возможности

- подписки: URL, Clash/mihomo YAML, base64, ссылки `vless`, `vmess`, `trojan`, `ss`, `hysteria2`/`hy2`, `tuic`;
- трафик и срок подписки (`subscription-userinfo`), обновление профилей;
- серверы с пингом, кнопка «Самый быстрый», автовыбор (`AUTO`);
- режимы: Умный (rule), Весь трафик (global), Напрямую (direct);
- системный прокси и TUN;
- живой график скорости и журнал ядра;
- Material You: фирменный оранжевый по умолчанию, свой цвет или системный акцент, светлая и тёмная темы;
- если ядро не принимает отдельный сервер из подписки, он пропускается, остальные работают.

## Сборка под Windows

Нужны [Flutter](https://docs.flutter.dev/get-started/install/windows/desktop) (stable, 3.47+)
и Visual Studio 2022 с компонентом «Desktop development with C++».

```powershell
flutter pub get
flutter build windows --release
```

Готовая программа — в `build\windows\x64\runner\Release\`.

### Ядро mihomo

Скачайте `mihomo-windows-amd64-*.zip` со страницы
[релизов mihomo](https://github.com/MetaCubeX/mihomo/releases), распакуйте и переименуйте файл в `mihomo.exe`.
brew ищет ядро в таком порядке:

1. путь, указанный в настройках;
2. переменная окружения `BREW_CORE`;
3. `core\mihomo.exe` рядом с `brew.exe`;
4. `mihomo.exe` рядом с `brew.exe`;
5. папка данных приложения `core\mihomo.exe`;
6. `mihomo` в `PATH`.

В артефакте Windows из GitHub Actions ядро уже упаковано в
`Release\core\mihomo.exe` и проверяется запуском `mihomo.exe -v`.
При локальной сборке ядро по-прежнему нужно скачать и положить туда вручную.

Для TUN программу нужно запускать от имени администратора.

### Android APK

Android использует только встроенное ядро Mihomo из `libmihomo-android` и системный
`VpnService`; sing-box в APK не подключается. При первом подключении Android запросит разрешение на VPN.
Инициализация Mihomo использует параметры `homeDir` и `profile`; подключение считается
успешным только после ответа локального Mihomo API на `/version`. Проверка конфигурации,
запуск VPN-сервиса и ожидание API ограничены по времени; при сбое приложение показывает
ошибку и останавливает только ту сессию, которую пыталось запустить.

GitHub Actions запускает Flutter-анализ и тесты, собирает **ARM64-only APK** для современных
64-битных Android-устройств, проверяет package, VPN service/permission и наличие нативных
библиотек Mihomo именно для `arm64-v8a`, а затем загружает артефакт `android-release-arm64`.
Это уменьшает размер APK за счёт исключения библиотек для `armeabi-v7a` и `x86_64`.
CI-проверки не заменяют тестирование на физическом телефоне и не доказывают передачу VPN-трафика.
Версия обёртки Mihomo закреплена на v0.3.7, SHA-256 проверяется при сборке Gradle.

Собственные правила Mihomo можно задать в настройках подключения, по одному
правилу на строку, либо добавить домен через короткую форму. Пользовательские
правила проверяются раньше правил из профиля подписки; правила самого профиля и
его rule providers сохраняются. Во время подключения главная страница показывает
активные соединения и совпавшее правило Mihomo, когда эти сведения доступны от API.
Срок и квота подписки отображаются только если их передал провайдер.

## Разработка

```bash
flutter analyze
flutter test
flutter run -d windows   # или -d linux
```

`BREW_NO_ANIM=all` (или `aurora,orb,chart`) отключает фоновые анимации — удобно для замеров.

## Структура

- `lib/core` — ядро: процесс mihomo, REST API, генерация конфига, разбор ссылок, системный прокси;
- `lib/state` — состояние приложения, профили, настройки;
- `lib/ui` — тема, экраны и анимированные виджеты.

Шрифты — DM Sans и Onest для кириллицы (SIL OFL 1.1, `assets/fonts/OFL-*.txt`).
